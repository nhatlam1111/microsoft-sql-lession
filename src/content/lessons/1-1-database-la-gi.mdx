## Từ file Excel đến một nguồn dữ liệu chung

Nếu đã quen Excel, bạn biết một **workbook** (file Excel) có nhiều **sheet** (trang tính). Khi mỗi phòng giữ một bản sao, hồ sơ được sửa ở bản này có thể chưa kịp sửa ở bản kia. Vì vậy, dữ liệu dùng cho cả công ty thường được đưa vào một nguồn chung.

### Database lưu dữ liệu

**Database** (cơ sở dữ liệu) là tập dữ liệu có cấu trúc, được phần mềm quản lý để nhiều người dùng theo quyền. Bạn có thể hình dung database giống một workbook, còn mỗi **bảng** trong đó giống một sheet. Điểm khác là các bên cùng đọc một nguồn thay vì mỗi bên giữ một bản riêng, nên thay đổi đã cập nhật vào nguồn thì mọi người đều thấy.

### SQL Server quản lý, SQL dùng để hỏi dữ liệu

Database không được mở như mở một file mà đi qua phần mềm quản lý. **SQL Server** là phần mềm của Microsoft quản lý việc lưu trữ, đọc và cập nhật database.

</figure>

Muốn lấy dữ liệu, bạn gửi yêu cầu bằng **SQL**: ngôn ngữ để hỏi và thao tác với dữ liệu. SQL Server xử lý yêu cầu đó rồi trả kết quả. SQL Server dùng **T-SQL (Transact-SQL)**, cách viết SQL của Microsoft.

### SSMS là công cụ làm việc với database

**SSMS** (SQL Server Management Studio) là công cụ cài trên máy Windows để kết nối tới SQL Server, xem các bảng, gửi câu lệnh và đọc kết quả. Dữ liệu nằm ở máy chủ, không nằm trong SSMS, nên đóng SSMS không làm mất dữ liệu. Người không viết SQL thường xem dữ liệu qua màn hình hệ thống hoặc báo cáo.

Bạn bắt đầu viết câu lệnh từ bài 1.6, trên web hoặc trong SSMS; chọn nơi thực hành ở [trang Giới thiệu](/microsoft-sql-lession/gioi-thieu/#chon-noi-thuc-hanh).

### Nguồn chung vẫn cần kiểm tra

Người thiết kế database có thể khai báo **luật dữ liệu**, như cột ngày chỉ nhận ngày, mã nhân viên không được trùng, mã phòng phải có trong danh mục. Khi luật đang bật, SQL Server từ chối dữ liệu vi phạm khi thêm hoặc sửa theo cách thông thường. Excel cũng có Data Validation để giới hạn dữ liệu nhập, nhưng phải thiết lập trong từng file.

Luật chỉ kiểm điều đã khai báo, nên **hợp lệ chưa chắc đã đúng**. `Kinh doanh` là phòng có trong danh mục, nên ghi nhầm một nhân viên vào phòng này vẫn lưu được. Database không tự biết ai thuộc phòng nào; người có quyền phải đối chiếu hồ sơ rồi cập nhật.

Ở bài này chỉ cần phân biệt database, SQL Server, SQL và SSMS, hiểu nguồn chung giúp gì và giới hạn của luật dữ liệu. Bài sau đi tiếp: bảng, dòng, cột ở bài 1.2, kiểu dữ liệu ở bài 1.3, khóa chính và khóa ngoại ở bài 1.4, các loại ràng buộc khác ở bài 5.2.

## Hay nhầm ở đâu

<Mistakes>

1. **Nghĩ database chỉ là Excel to hơn.** Chỉ tăng dung lượng file không giải quyết việc mỗi người sửa một bản.
2. **Sửa file xuất rồi coi như đã sửa nguồn.** Danh sách xuất sang Excel chỉ phản ánh dữ liệu lúc lấy; sửa trong file không đổi dữ liệu ở nguồn.

</Mistakes>

## Ứng dụng

<Apply>

- **Nói đúng tên khi trao đổi với IT:** phân biệt database, SQL Server và SSMS khi xin quyền truy cập hoặc báo lỗi kết nối.
- **Chọn đúng nơi lấy dữ liệu:** lấy số liệu từ nguồn chung thay vì so các file đang gửi qua lại.

</Apply>
